# Un solo lfs.sh — piano di lavoro

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** un solo `lfs.sh`: `sudo bash lfs.sh fase10` crea (o aggiorna) da solo la macchina virtuale con Arch + Vetro, `sudo bash lfs.sh avvia` la accende; dentro Arch `sudo bash lfs.sh installa` fa quello che faceva `vetro-arch.sh`.

**Architecture:** il file unico di oggi (`arch/src/*.sh` + archivio di `arch/file`) diventa `arch/dist/lfs.sh` e si aggiunge il pezzo "PC" (`arch/src/80-pc.sh`): QEMU, ISO, disco, server HTTP locale. Arch si installa dentro la macchina con lo script `installa-arch` (eseguito dalla ISO con `script=`); i comandi successivi arrivano alla macchina dalla cartella condivisa (`.comando`) e li esegue il servizio `vetro-comando`.

**Tech Stack:** Bash, QEMU, archiso (`script=`), pacstrap/arch-chroot, systemd, GRUB BIOS, 9p.

**Spec:** `docs/superpowers/specs/2026-11-04-lfs-unico-design.md`

## Global Constraints

- Comandi: `fase10`, `avvia`, `registri`, `controlla`, `installa`, `rifai PASSO`; senza comando l'aiuto.
- Cartella sul PC: `~/vetro-arch` dell'utente di `sudo` (`SUDO_USER`); disco `disco.qcow2` 40G; condivisa `condivisa/` → `/mnt/vetro` (9p, `mount_tag=vetro`).
- Server: solo `127.0.0.1:8765`; dalla macchina `http://10.0.2.2:8765`.
- Password: mai in chiaro fuori dal PC; impronte `openssl passwd -6`.
- QEMU come `SUDO_USER`, mai come root.
- Il vecchio `lfs.sh` in cima al progetto non si tocca; il nuovo e' `arch/dist/lfs.sh`.
- Prove: `bash arch/test/esegui.sh` → `=== TUTTO OK`.

## Review Focus

- **`fase10` rilanciato a meta'** (rete caduta durante l'installazione di Arch): disco mezzo fatto → si ricomincia l'installazione di Arch (il segno "Arch installato" si scrive solo alla fine) → prova `test_fase10_riprende` (Task 3).
- **QEMU senza 9p**: i comandi arrivano dal server HTTP → prova `test_comando_da_http` (Task 2).
- **Password con spazi e simboli**: l'impronta si fa da stdin, niente problemi di virgolette → prova `test_impronta_password` (Task 3).
- **Lanciato senza sudo o su Arch per `fase10`**: messaggio chiaro → prova `test_serve_root_pc` (Task 3).
- **Accensione normale senza comando**: `vetro-comando` non fa niente e non spegne → prova `test_senza_comando` (Task 2).

### Task 2: Installazione di Arch e servizio dei comandi

**Files:** Create `arch/file/usr/local/lib/vetro/installa-arch`, `arch/file/usr/local/sbin/vetro-comando`, `arch/file/etc/systemd/system/vetro-comando.service`, `arch/test/test-pc.sh`

**Interfaces:**
- `installa-arch` (bash, gira nella ISO; legge `installa.conf` con `UTENTE`, `IMPRONTA`, `IMPRONTA_FANTASMA`, `SERVER`): uscita anche su `/dev/ttyS0`; partiziona `/dev/vda` (DOS, una partizione), `mkfs.ext4 -F -O encrypt -L vetro`, `pacstrap -K /mnt base linux linux-firmware e2fsprogs grub sudo`, `genfstab -U`, configura (fuso, lingua, tastiera, nome, utente, `wheel`), scarica `lfs.sh` dal server ed estrae (`lfs.sh _estrai`) `10-cavo.network`, `vetro-comando`, `vetro-comando.service`; GRUB `i386-pc` con `console=tty0 console=ttyS0,115200`; riga 9p in fstab; `systemctl enable systemd-networkd systemd-resolved vetro-comando`; `/etc/vetro/utente`, `/etc/vetro/fantasma.hash` (0600), `lfs.sh` in `/usr/local/sbin/lfs.sh`, segno `/etc/vetro/arch-installato`; `poweroff`. Ogni errore → messaggio "INSTALLAZIONE NON RIUSCITA" sulla seriale e `poweroff`.
- `vetro-comando` (bash, nella macchina; rispetta `VETRO_RADICE` per le prove): se c'e' `/mnt/vetro/.comando` (o lo da' `curl -fs http://10.0.2.2:8765/.comando`, con `lfs.sh` dallo stesso server) → toglie il file, copia `lfs.sh` in `/usr/local/sbin/lfs.sh`, `bash lfs.sh COMANDO`, poi `systemctl poweroff`; senza → esce 0.
- Servizio: `After=network-online.target local-fs.target`, `Wants=network-online.target`, `Type=oneshot`, `StandardOutput=journal+console`, `TimeoutStartSec=infinity`, `WantedBy=multi-user.target`.

- [ ] **Step 1: Test** in `test-pc.sh`: `test_installa_arch` (`bash -n`; contiene `pacstrap -K /mnt base linux`, `grub-install --target=i386-pc /dev/vda`, `console=ttyS0`, `mount_tag`/riga 9p `vetro /mnt/vetro 9p`, `chmod 600`, `INSTALLAZIONE NON RIUSCITA`), `test_comando_da_cartella` (radice con `mnt/vetro/.comando`=`registri` e `lfs.sh` finto → `lfs.sh registri` chiamato, `.comando` tolto, `systemctl poweroff` chiamato), `test_comando_da_http` (niente cartella, `curl` finto che da' `controlla`), `test_senza_comando` (niente → nessuna chiamata, uscita 0), `test_servizio` (valori sopra).

### Task 3: La parte "PC": fase10, avvia, registri, controlla

**Files:** Create `arch/src/80-pc.sh`; Test `arch/test/test-pc.sh`; Delete `arch/vm/vetro-vm.sh`, `arch/test/test-vm.sh` (la loro logica passa qui)

**Interfaces (tutte usano `esegui` per i comandi esterni, cosi' si provano):**
- `pc_cartella` → `~/vetro-arch` di `SUDO_USER`; `pc_utente` → `SUDO_USER` (root se manca).
- `pc_qemu_pronto` (installa `qemu-system-x86 qemu-img` con dnf o apt se manca); `pc_iso` (scarica da `https://geo.mirror.pkgbuild.com/iso/latest/`, controlla con `sha256sums.txt`, sceglie la ISO con la data, come `scegli_iso`).
- `pc_parametri_iso CARTELLA_ISO -> "archisobasedir=arch archisosearchuuid=…"` (o `archisolabel=…`) dai file `*.conf`/`*.cfg` della ISO.
- `pc_impronta` (stdin → `openssl passwd -6 -stdin`); `pc_chiedi_utente` (scrive `condivisa/installa.conf`; nelle prove `VETRO_UTENTE`, `VETRO_PASSWORD`, `VETRO_PASSWORD_FANTASMA`).
- `pc_qemu MODO` (`installa` | `comando` | `avvia`) → riempie `COMANDO` (array): `installa` con `-kernel -initrd -append "... script=http://10.0.2.2:8765/installa-arch console=ttyS0"` + `-cdrom`, `-display none -serial stdio`; `comando` senza schermo con 9p; `avvia` con schermo come `vetro-vm.sh` (virtio-vga-gl `max_outputs=2`, `usb-tablet`, audio, 9p). `--prova` scrive il comando invece di lanciarlo.
- `pc_fase10`: serve root, non su Arch; QEMU; cartella; se manca `condivisa/.arch-installato`: chiedi utente, ISO, disco, kernel dalla ISO (`mount -o loop,ro`), server, macchina in modo `installa`; quando torna, il segno lo scrive il PC solo se la macchina ha scritto `condivisa/.arch-ok` (via 9p non c'e' ancora: lo scrive `installa-arch` col server HTTP, metodo PUT). Poi `.comando`=`installa`, copia di `lfs.sh`, macchina in modo `comando`. Fine: "Fatto. Ora: sudo bash lfs.sh avvia".
- `pc_avvia`, `pc_comando registri|controlla`.
